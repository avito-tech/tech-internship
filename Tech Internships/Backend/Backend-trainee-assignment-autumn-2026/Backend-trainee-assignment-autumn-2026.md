## **Тестовое задание для стажёра Backend (осенняя волна 2026\)**

В Авито рождается много идей, одна из таких — сервис Авито.Кухня. В рамках MVP необходимо спроектировать и реализовать API сервис, который расширяет основной функционал площадки.   
   
Главная цель задания — показать ваш подход к проектированию backend-системы и принятию технических решений. Реализация нужна, чтобы продемонстрировать этот подход на практике. Не стремитесь сделать production-ready решение: допустимые упрощения можно описать и обосновать в README.  
 

## **Бизнес задача**  
Спроектируйте и создайте MVP веб\-приложение, которое:  
   
**Предоставляет API для ресторанов/кафе/магазинов**  
В рамках MVP планируется предоставить закрытый доступ некоторому списку заведений, которые смогут работать через площадку и принимать заказы пользователей на доставку еды. Состав API продумайте сами.  
   
**Предоставляет API для интеграции клиентской части**  
В рамках MVP планируется только web версия, которая должна взаимодействовать с вашим API. Клиент будет реализовываться по вашему CJM. Авторизацию и аутентификацию пользователей реализовывать, как и клиентскую часть, не нужно! Состав API продумайте сами.
   
## **Что нужно реализовать**  
   
Разработку нужно вести в одном репозитории.  
   
**Основные сценарии**  
Всё начинается с пользовательского сценария. Необходимо продумать как человек, зашедший на Авито.Кухня, будет производить заказы. Важно продумать несколько основных сценариев — например, наличие товара в заказе, меню и т. д.  
Вы можете продумать то количество сценариев, которые сочтете нужным. Главная цель — чтобы сценарии отвечали на вопрос, как человек находит товар и с какими трудностями сталкивается.  
   
При этом важно проработать CJM и со стороны заведения, которое размещено в Авито.Кухня. Об этом пункт ниже.   
   
**Заведения**  
Для демонстрации интеграции необходимо реализовать в том же репозитории пример одного заведения (отдельный сервис, реализованный на выбранном кандидатом языке и запускаемый вместе с основным приложением через Docker Compose). Сервис должен взаимодействовать с API вашего основного сервиса и в случае необходимости предоставлять свой API для обмена информацией.  
   
**Спроектировать API и схемы БД**  
Критически важно правильно спроектировать систему, т. к. после проведения MVP нужно будет масштабировать решение. В репозитории должны находиться схемы для миграций и OpenAPI спецификация. Подумайте, как связать данные в вашей системе с данными заведений и пользователями.

## **Стек**  
- Язык программирования: предпочтительно Golang, Python (или любой другой, на котором вы хотите реализовать сервис).  
- База данных: выбрать самостоятельно  
- Запуск приложения: поднимается через Docker Compose  
- Качество кода: необходимо настроить линтер и/или инструменты статического анализа, подходящие для выбранного языка. Конфигурация используемых инструментов должна находиться в репозитории.   
- По желанию: использовать кодогенерацию для API  
   
## **Использование ИИ**  
Авито — AI-first компания. Мы рекомендуем для написания кода использовать ИИ (любой доступный вам агент), но помните, что за архитектуру и качество вашего кода отвечаете вы сами\! Будьте готовы ответить на вопросы интервьюера по сгенерированным частям задания в случае прохождения на следующий этап. Будет плюсом, если приложите промпт (plan), по которому был написан проект.  
   
## **Критерии приёмки работы**  
- Приложение поднимается и выполняет все бизнес-сценарии, которые были поставлены перед ним.  
- Наличие CJM со стороны пользователей и ресторанов в формате code-generated диаграмм (PlantUML или аналог).  
- Наличие миграций со схемами БД, OpenAPI схема.  
- Продуман и оформлен readme, где есть: описание проекта, описание архитектуры (C4 диаграмма. Достаточно Level 2/Level 3 на ваше усмотрение), описание схемы БД.
